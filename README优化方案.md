## 一、核心诊断：一个文档想同时服务三类读者

"顺序混乱"的根因不是段落排错了，而是 **README 在同时干三份文档的活**：


| 读者            | 他想要什么             | 现在在哪                         |
| ------------- | ----------------- | ---------------------------- |
| **考研学员**（主目标） | 怎么装、每天怎么用         | 第 651 行才出现，前面要滚过 650 行功能清单   |
| **评估者 / 开发者** | 架构、能力边界、值不值得 star | 散落在 97\~551 行                |
| **贡献者**       | 目录结构、测试、怎么改       | 目录树在第 787 行（倒数第二），测试在第 742 行 |


结果：**学员被劝退，贡献者找不到入口，你自己维护也累**（`操作手册.md` 365 行与 README 大面积重复，改一处要改两处）。

## 二、7 个具体问题（按严重度排序）

### 1. 上手指南埋在全文 70% 处 ⛔ 最致命

`## 🚀 用户本地化部署与快速上手流程` 在**第 651 / 931 行**。读者要先看完 15+ 工具矩阵、27 条子命令大表、8 小节招考情报、TUI 全屏 ASCII 图、6 Tab 看板详解……才能知道怎么装。

GitHub 的现实是：**首屏 3 屏决定去留**。现在 README 的前 3 屏（1\~150 行）是"这是什么 + 三类学生画像 + 四大辅导风格 + ky-cli 自述"——全是"我做了什么"的作者视角，没有一句"你现在该敲什么命令"。

| ------------------------------- | --------------- | -------------------------------------------------- |

### 5. 编号与导航错误

- 看板章节出现**两个 `### 3.`**（395 行"隐私脱敏"、403 行"KaTeX 伴侣"），应为 3/4/5；
- 顶部导航 9 个锚点**按文档顺序排**（"这是什么"第一、"快速开始"最后）——导航的作用是引导，应把"快速开始"放第一；
- 导航锚点 `#-终端全景智能中枢-tui-v25-控制台` 与正文标题 `TUI v2.5 极客控制台` 不一致，锚点会失效。

### 6. 徽章墙 13 个，过半是自证型

`Status-Sprint 7 Delivered`、`Tests-251/251 Passed`、`Agent Core-Claude Code Level`、`KaoYan Intelligence 55+高校` 都是**手写静态 badge**（shields.io 只是把你的文字画成图，不代表任何验证结果）。

问题有二：① 数量多反而稀释可信度；② "Claude Code Level"这类自评放徽章位，恰好是挑剔的开发者（你真正的种子用户）最容易反感的地方。

**建议**：保留 5\~6 个客观徽章（Python 版本 / License / Live Demo / Stars / CI 状态用真实 workflow badge），把"251 项测试"挪到正文用一行命令 + CI badge 表达。

### 7. ⚠️ 版本声明三处打架（顺带发现的真问题）


| 位置                 | 声明                                                                                  |
| ------------------ | ----------------------------------------------------------------------------------- |
| README:656 / :907  | Python **3.8+**                                                                     |
| requirements.txt:5 | Python **3.10+**                                                                    |
| **代码实际**           | **3.12+**（`tools/ky_cli.py:118` 仍是 f-string 表达式含反斜杠，Python &lt;3.12 直接 SyntaxError） |


我用 Python 3.11 实测：`SyntaxError: f-string expression part cannot include a backslash at line 118`。**上次报告里的 P0-1 还没修**——而 README 承诺"3 分钟开箱"。
修复只需一行：把 `str(target_path).replace("\\", "/")` 提到 f-string 外赋给变量再嵌入。修完可回到 3.11；再处理 `tools_impl.py` 的 `Path.is_relative_to()`（3.9+ API）即可真正支持 3.8。

## 三、解决方案：文档三层分治

```
README.md        门面 + 决策 + 上手入口        目标 200~260 行   ← 只做"让人决定用 + 知道下一步去哪"
操作手册.md      学员主文档（已存在，扩写）     目标 400~500 行   ← 从安装到日常 SOP 到全部命令
SETUP.md         进阶配置（已存在 467 行）                        ← 模型/MCP/IM/看板二次开发
docs/ARCHITECTURE.md 或 CONTRIBUTING.md（新建）                  ← 目录树/测试/架构/AI Agent 接入/贡献
```

**README 的唯一职责**：让访客在 30 秒内判断"要不要用"，然后把他**分流**到正确的文档。

### 排版技巧

1. **`<details>` 折叠长内容**：命令全表、TUI 图、可选依赖清单；
2. **导航按读者分组**（新手 / 进阶 / 开发者），而不是按文档顺序；
3. **每个能力章节统一节奏**：`痛点 → 机制 → 一句命令 → 详见手册`，读起来有呼吸感；
4. **高频命令前置**：`ky menu` / `ky status` / `ky today` / `ky compose` 等 8 条放正文，其余折叠；
5. **加入"30 秒判断"**：直接写清 ✅ 适合 / ❌ 不适合，比任何功能罗列都更能建立信任。
