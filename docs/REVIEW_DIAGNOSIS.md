## 四、测试资产：投入充足，组织混乱

### 4.1 命名现状（213 个测试文件）

| 命名模式 | 数量 | 问题 |
| --- | --- | --- |
| `test_fix*` 前缀 | **63** | 只说明"修了个 bug"，不说明测什么 |
| 带日期戳（如 `_20261005`） | **49** | 只有作者知道那天修了什么 |
| 带批次号（`w3` / `w11` / `r3` / `c3` / `ut4` / `audit` / `challenger`） | **124** | 批次编号是项目内部黑话 |
| 合规命名（模块 + 行为） | 少数 | — |

按前缀聚合的实况：`fix` 63、 `audit` 9、`search` 8、`w11` 6、`security` 6、`dashboard` 5、`ut4` 4、`grading` 4……

### 4.2 分层现状

`tests/` 下**仅有两个子目录**：`benchmarks/`、`fixtures/`。其余 213 个文件**全部平铺在根目录**，无 unit / integration / e2e / regression 分层。

### 4.3 后果

1. **无法回答"某模块覆盖率如何"** —— 想知道 `exam_grading` 被测了多少，只能靠猜；
2. **新人不认识** `test_w11_search_cooldown.py` 守护的是什么；
3. **只能全量回归** —— 改一个小函数也要跑完 4022 项测试；
4. **测试自身成了技术债** —— `run_tests()` 2408 行 / CC 399，比它测的业务代码还难改。

## 五、流程侧缺口

| 缺口 | 现状 | 影响 |
| --- | --- | --- |
| `.github/CODEOWNERS` | ❌ 缺失 | L2/L3 变更无法自动指派 Owner |
| `.github/PULL_REQUEST_TEMPLATE.md` | ❌ 缺失 | 审查标准靠口口相传 |
| 审查清单 | ❌ 缺失 | 不同审查者尺度不一 → **这就是"参差不齐"的流程根因** |
| 静态门禁 | ⚠️ 仅 `lint_check.py`（5 类语法规则） | 复杂度/架构/测试质量无约束 |
| ruff / mypy 配置 | ❌ `pyproject.toml` 中无对应 `[tool.*]` | 风格一致性无工具保障 |
| 提交粒度 | ⚠️ 大量巨型批次提交 | 单次提交含数十项修改，难以审查与回滚 |
| CI 流水线 | ✅ 3 个 workflow，含多平台多版本、工作台污染守卫、评测集门禁 | 基础良好 |

**已有优势（应保留并强化）**：
- 隐私保护体系完整（`privacy_policy.py` 1766 行、内容级脱敏、阴性对照测试）
- 安全加固扎实（配置/网络守卫、权限分级 L0–L5、审计降级标记）
- **变异检验实践**（CHANGELOG 记录"20 轮变异检验全部精确捕获"）—— 这是相当先进的做法，应固化为 L3 强制项
- 离线评测集（考纲守卫 137 条、引文忠实度 109 条）纳入 CI

## 六、结论

> **本项目的代码质量问题，不是"写得差"，而是"缺少约束生长的轨道"。**

证据：无硬编码凭据、无重复代码、裸 except 已清零、测试投入 7 万行、已有变异检验 —— 这些都说明团队能力在线。但在缺少规模约束、测试组织规范和审查清单的情况下，每个开发者按自己的习惯生长，16 万行代码自然呈现出参差。

**因此解决方案不是"重写"，而是"装轨道"**：
1. 用 `review_gate.py` 卡住**新增代码**（存量不追溯）→ 止血；
2. 用 `CODE_REVIEW.md` 统一**审查尺度** → 治本；
3. 用《技术债清单》按优先级**逐季偿还**存量 → 收敛。

## 七、90 天落地路线

| 阶段 | 时间 | 动作 | 验收 |
| --- | --- | --- | --- |
| **P0 埋点** | 第 1–2 周 | 合入 `review_gate.py`，CI 中**只报不卡**；生成 `baseline.json` 并提交 | 团队看到真实数据，就阈值达成共识 |
| **P1 止血** | 第 3–4 周 | `review_gate.py --diff` 转**阻塞**（仅卡新增代码）；新增 `CODEOWNERS` + PR 模板 | 新增代码红线违反率趋近 0 |
| **P2 治本** | 第 5–8 周 | 全员按 `CODE_REVIEW.md` 执行分级审查；新测试一律进分层目录；L3 强制变异检验 | 审查首响符合 SLA；`test_fix_*` 零新增 |
| **P3 偿还** | 第 9–12 周 | 按 Top 10 清单偿还 2–3 个高危巨石函数（**先补测试再重构**） | CC>25 函数数下降；对应模块有可定位的测试 |
| **P4 收敛** | 持续 | ruff/mypy 渐进接入；测试资产分批迁入分层目录；季度 20% 容量还债 | 月度指标持续改善 |

**每一步都先"只报不卡"再转阻塞** —— 这是避免门禁被绕过的唯一可靠方式。
