不要把高校信息查询做成普通搜索，而应该做成一个“高校招生信息检索 Agent”，核心目标是：

> 找到官方来源 → 进入官方页面 → 提取结构化数据 → 多源交叉验证 → 给出来源和时间 → 无法确认时明确告诉用户。



这正好可以成为 kaoyan_chain 的核心差异化能力。

目前研招网本身已经提供招生单位、硕士专业目录等结构化入口，而且明确说明数据由招生单位上报；研招信息公开平台的录取公开信息也由各招生单位提供并在其网站公示。

搜索引擎没有收录

robots / WAF / CDN

同一个学校同时存在研究生院、研招网、学院招生网

同一信息出现多个年份版本


你自己已经遇到的“搜索到了但打不开高校网站”，实际上是这个领域最核心的技术问题之一。

甚至几年前的高校信息爬虫项目就明确指出，不同高校的链接命名和网页内部组织方式差异非常大，难以用简单规则统一抓取。

所以不要做：

SearchTool

而应该做：

UniversityResearchEngine

六、第三步：不要只用 requests，要加入 Playwright

这一点非常重要。

七、甚至可以直接“监听高校网站自己的 API”

这是我非常推荐你的一个增强点。

假设：

https://xxx.edu.cn/admission

表面上没有招生信息。

但页面可能请求：

/api/news/list
/api/article?id=12345
/api/admission/search

Playwright 可以监听 network：

page.on("response", ...)

例如：

async def capture_api(page):
    responses = []

    page.on(
        "response",
        lambda response:
            responses.append(response.url)
            if "/api/" in response.url
            else None
    )

    await page.goto(url)

    return responses

然后发现：

/api/article/20260904/1234

再直接读取 JSON。

这通常比：

解析复杂网页

稳定很多。

Playwright 官方文档明确支持监听 request / response 以及等待特定 response。

class UniversityCrawler:

    async def crawl(self, university, query):

        urls = await resolver.discover(university)

        for url in urls:

            result = await http_fetch(url)

            if result.is_valid:
                return result

            result = await playwright_fetch(url)

            if result.is_valid:
                return result

        return None
